## Operator-gateway's five constraints, assessed honestly

Its own header states the contract:

> *"SANDBOX DRY-RUN + CONTROLLED REAL-LOCAL FOUNDATION MODE â€¦ no production DB writes, no external execution, no live runner, no API keys, no web-session scraping. No real execute button."*

**Would any current check catch the loss of each?**

| # | Constraint | Caught? | Reasoning |
|---|---|---|---|
| **OG1** | **No production DB writes** | **PARTIAL** | C4 catches an *added* `.insert/.update/.upsert/.delete(`. It does **not** catch: a write via `.rpc(`, a write through an existing call whose target changed to a prod ref, a write through a helper outside the graph, or a write where the count stays level because another call was removed. | **OG2** | **No external execution** | **NO** | `child_process`, `exec`, `execSync`, `spawn`, `fork` are **not tracked by any check**. Zero coverage. A ported file could shell out and every check would pass. |

Missing defect classes absent from G1-G10:

1. **Auth/permission boundary drift**  
A port can expose an operator page/API to the wrong role or unauthenticated users while construct counts stay flat. C1-C8 do not model route protection, middleware reachability, session checks, or role predicates. Bounded if encoded as route-to-policy assertions; otherwise architectural evidence. Threatens OG5 and indirectly OG1-OG3.

2. **Target/environment misbinding**  
Same DB/API call count, but the Supabase project, URL, branch, tenant, or runtime mode points at production. C4 sees constructs, not destinations or trust zones. C8 might spot it manually, but that is not a check. Requires config/runtime evidence unless all bindings are statically declared. Directly threatens OG1 and OG3.

3. **Import alias / path resolution drift**  
A port can import a similarly named helper from the target app instead of the source-equivalent helper, silently changing behavior. C1 proves declared provenance exists, not that module resolution preserves behavior. Bounded with import-resolution comparison plus allowlist. Threatens OG1-OG5 depending on helper.

4. **UI-to-handler wiring drift**  
A visually identical disabled/dry-run control can be wired to a real handler, or a no-op handler can be replaced while JSX shape/counts remain stable. G3 says runtime behavior generally, but the map does not name event binding as its own defect class. Needs render/interaction tests or static handler provenance. Directly threatens OG5, OG2, OG3.

5. **Policy inversion / predicate weakening**  
`if (dryRun) return` becomes `if (!dryRun) return`, or an allowlist becomes a denylist. Counts do not change; type/build pass. Bounded only with semantic tests or invariant-specific static assertions. Directly threatens all OG constraints.

6. **Secret exfiltration without named API keys**  
Code can forward existing cookies, bearer tokens, local storage, headers, or session data to an internal route or remote dependency without adding literal API key names. C4 key matching is too narrow; fetch count may stay level. Partly bounded with taint-style scans, better with runtime network interception. Threatens OG4 and can enable OG1-OG3.

7. **Persistence outside DB writes**  
Writes via cookies, localStorage, IndexedDB, filesystem-backed cache, queues, logs, analytics, or webhook side effects are not covered by `.insert/.update/.upsert/.delete(`. Bounded for known browser/server APIs; runtime needed for external services. Threatens OG1 if “no production writes” means more than Supabase row writes.

8. **Generated/build-time code drift**  
A safe source file can generate unsafe target code through build plugins, codegen, route handlers, or config transforms. C4 scans source graph, not generated artifacts. Requires build artifact inspection or architecture constraints. Threatens OG2-OG5.
